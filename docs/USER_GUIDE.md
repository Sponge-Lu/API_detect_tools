# API Hub Management Tools - 用户使用指南

## 简介

**API Hub Management Tools** 用于管理和运维多个 API 中转站，适合同时维护多站点、多账号、CLI 配置和代理路由的用户。

当前版本为 **v3.0.4**。相较 `v2.1.24`，最明显的变化是：

- 新增 `数据总览` 首页，并将站点数据与路由数据拆为子页
- 本地路由升级为 Messages、Chat Completions、Responses 通用 HTTP 网关
- 新增并行的 `模型映射` 与 `配置文件` 页面，以及会话级模型/思考强度覆盖
- 新增 `日志` 页，支持会话事件与路由请求尝试两类子页
- 支持账号级自动刷新
- 主界面重构为侧边栏工作台
- 主题系统收敛为 `Light` / `Dark`

---

## 界面结构

当前一级页面包括：

- `数据总览`
- `站点管理`
- `LDC 积分`
- `本地路由`
- `模型映射`
- `配置文件`
- `路由日志`
- `设置`

说明：

- `数据总览` 包含 `站点数据` 与 `路由数据` 两个子页。
- `本地路由`、`模型映射`、`配置文件` 是三个相互独立的一级页面。
- 直连配置与托管站点统一在 `站点管理` 中维护；路由日志使用独立一级页面。

### 视觉与主题

- 使用统一产品级原语：`AppButton`、`AppInput`、`AppModal`、`DataTable`、`AppCard`、`AppIcon`
- 主题仅保留两套预设：`Light`、`Dark`
- 默认窗口尺寸：`1400 x 900`
- 最小窗口尺寸：`1200 x 700`

## 核心功能

### 1. 站点与账号管理

- 在一个页面中维护多个 API 站点
- 支持站点分组、排序、搜索和缓存数据展示
- 支持一个站点绑定多个账号
- 支持按账号配置自动刷新开关和间隔
- 支持按浏览器 Profile 直接打开站点

### 2. 自动认证与登录

- 添加站点时可直接输入 URL，通过浏览器登录后自动捕获凭证
- 若登录后站点未返回 `access_token`，系统会尝试自动补建令牌
- 遇到 Cloudflare 或挑战页时，会回退到浏览器模式
- 登录浏览器与检测浏览器已分离，减少批量检测和登录流程冲突

### 3. 站点检测与统计

- 查看余额、今日消费、请求数、RPM、TPM、模型数量等指标
- 批量检测时支持逐站即时更新
- 支持站点级与账号级自动刷新
- 支持全局排序，排序状态会自动保存

### 4. API Key 与签到

- 可视化创建、删除、查看 API Key
- 支持配额、过期时间、分组等参数
- 自动检测签到能力
- 支持单站签到与批量签到
- 支持浏览器模式完成被挑战站点的签到

### 5. 接入点协议与端点测试

- 接入点详情的“测试”页提供 Messages、Responses 与 Chat Completions 三个独立原生测试
- 页面顶部“路由上游协议”只决定真实路由是否转换协议，不会改写测试请求
- 每个端点单独选择 API Key 和模型；托管站点默认按所选 Key 的用户分组列出模型，也可切换为全部模型，直连配置列出已获取与手工补充的全部模型
- 测试统一发送“1.2和1.19哪个更大？”，不发送客户端特征
- 测试完成后会显示成功/失败、简短失败原因、响应摘要、耗时和最近测试时间

### 6. 数据总览

`数据总览` 是当前默认首页，分为两个子页：

#### 站点数据

- 查看站点余额、今日消费、请求量、Token 与模型数量
- 查看站点每日快照趋势
- 查看签到状态与站点资源榜单

#### 路由数据

- 查看路由请求量、成功率、Token 与首字响应 / 会话时间分位数
- 按全部、站点或自定义 CLI 过滤路由桶级数据
- 使用运行趋势、模型热力、通道散点和模型到通道 Sankey 分析路由健康
- 运行趋势支持 `24h` 与 `7d` 视窗；即使当前只有部分路由桶数据，也会显示完整小时 / 日期 X 轴，首个真实数据点之前的空桶只显示时间标签

### 7. 本地路由

`本地路由` 在 `http://127.0.0.1:3210` 提供通用网关。任何客户端只要使用 `/v1/messages`、`/v1/chat/completions` 或 `/v1/responses` 并携带统一 API Key，就能进入同一模型映射、优先级和故障转移流程，不需要先登记客户端名称。

- 页面可启停服务，维护统一 API Key、上游代理和浏览器 Origin 白名单
- 隐藏兼容入口 `GET /v1/models` 供客户端模型选择器使用，不会触发上游模型拉取
- 会话路由以 Agent、稳定运行位置和 Session ID 共同区分实例。可以先只选择模型与思考强度，为下一个新会话创建等待路由；首条完整路由键请求会自动补全紧凑卡片，并以预创建的模型和思考强度覆盖该请求携带的值。同一运行位置切换 Session 时旧路由关闭，长时间无请求不会自动关闭。卡片固定为三列和固定宽度，窗口变窄时横向滚动，不改变列数
- 代理优先消费完整的 `x-api-detect-agent-id`、`x-api-detect-runtime-slot-id`、`x-api-detect-session-id`，并可使用对应展示名称 Header。当前 Codex 请求会从原生窗口 Header 和 `client_metadata` 会话字段自动组成稳定键；Claude Code 请求会使用原生 `x-claude-code-session-id`。两者都无需修改静态 CLI 配置；没有稳定物理窗口标识时，卡片显示“会话级路由”。Codex 不会把 `sessionId:上下文窗口编号` 当成运行位置。缺少、冲突或不合法时请求仍正常路由，但不会创建会话路由实例或占用等待中的预创建路由
- 静态 CLI 配置只用于生成并应用本地配置文件，不参与会话路由身份识别；应用内部身份 Header 不上送，客户端原生协议 Header 保持原样转发
- “识别规则”弹窗提供 Header、Query、JSON 路径、命名空间、协议、正则和长度限制；示例包括 `x-session-id`、`session_id`、`metadata.session_id`
- 记录扫描得到的会话标记为“仅候选”，可以在首条请求前保存模型和思考强度；命中相同 HTTP session ID 后才变为精确关联并生效
- “打开中”只显示对话记录明确报告为打开或当前选中的 session，不再根据最后请求距今多少分钟推断；窗口长期打开但没有对话时仍保持打开
- “预配置会话”可在请求前录入命名空间、稳定 session ID、显示名、模型和思考强度；保存后在“全部”范围可见，清理活动记录不会删除它
- 未携带稳定会话 ID 的请求始终按自身字段逐请求路由，不按端口、API Key、时间或内容合并
- 自定义思考强度保持原字符串，不自动降低档位

### 8. 模型映射

- 创建重定向模型并选择原始模型来源
- 调整站点、API Key 优先级、禁用状态和运行时熔断策略
- 会话选择的逻辑模型仍经过本页映射与故障转移，不直接绑定某个账户

### 9. 配置文件

- 新建任意名称的配置卡片；Claude Code、Codex、OpenCode、Grok Build 只是默认示例
- 每张卡片可选择本地路由、可用站点账户或完整直连配置；禁用站点、失效 Key 和不完整直连不会出现在可选列表
- 模型按目标隔离：本地路由显示重定向模型，站点默认显示所选 Key 分组模型，`显示全部` 只显示该账户原始模型，直连显示已拉取与手动模型
- 每个文件独立填写路径、格式、模板/静态内容和 Base URL/API Key/模型替换字符
- `应用到本地` 可选择合并或覆盖；JSON、TOML、ENV 支持结构化合并，纯文本需显式覆盖，解析失败不会写入
- `本地文件` 视图用于重新读取、直接编辑和保存磁盘真实内容，与模板应用预览完全分离
- 可选 JSON/JSONL 对话记录路径用于补充标题、工作区和稳定 ID；“打开状态路径”读取每条记录自身的窗口状态；JSON 顶层状态需同时配置“窗口打开状态路径”和“窗口当前 Session ID 路径”，只有窗口明确打开且 ID 匹配时才进入“打开中”，残留 ID、文件时间和最近请求都不会被当作窗口打开

### 10. 路由日志

- `会话事件` 展示当前 renderer 会话中的通知与关键操作
- `路由日志` 展示本地路由代理逐条请求尝试
- 路由日志以无卡片、带表头的横向滚动单行表格展示 CLI 图标、请求 / 重试、原始模型、路由目标、Token（总 / 输入 / 输出 / 缓存写 / 缓存读）、参考金额、用时 / 首字、纯数字状态码与时间；失败尝试会在第二行显示错误信息
- 直连配置来源会以 `直连配置 / 配置名` 展示；站点 / 账户 / 分组 / API Key 路径仅适用于普通站点来源

### 11. Linux Do Credit

- 读取 `credit.linux.do` 的余额、收入、支出、交易记录
- 查看最近统计数据
- 选择支持 LDC 支付的站点并发起充值跳转

### 12. 备份、恢复与更新

- 本地自动备份稳定配置
- 从历史备份恢复
- 使用 WebDAV 进行 manifest 配置包云端备份
- 应用内检查更新、下载和安装
- 配置损坏时会优先尝试从最近备份恢复
- 运行态缓存、路由状态、探测历史和分析桶已拆分到 bounded sidecar 文件，避免高频运行态写入污染 `config.json`

## 常用使用路径

### 添加站点

1. 打开 `站点管理`
2. 新建站点并填写 URL
3. 选择自动登录或手动输入凭证
4. 登录完成后等待系统抓取账号信息

### 配置账号级自动刷新

1. 打开站点详情或账户相关入口
2. 为目标账号设置 `auto_refresh`
3. 设置刷新间隔，最小为 15 分钟
4. 保存后等待定时器生效

### 套用客户端配置

1. 打开 `配置文件`，复制一个示例或新建卡片
2. 选择本地路由、站点账户或直连配置目标
3. 为各文件填写路径、格式、模板或静态内容和替换字符
4. 点击 `应用到本地`，选择 `合并` 或 `覆盖` 并检查最终写入内容
5. 确认后以事务方式写入；若要手工编辑磁盘内容，切换到 `本地文件`

### 使用 Route 工作台

1. 在侧边栏进入 `本地路由`
2. 配置代理服务端口与统一 API Key
3. 在 `模型映射` 创建逻辑模型及候选优先级
4. 在 `数据总览 -> 路由数据` 查看路由统计图表
5. 在 `日志 -> 路由日志` 查看逐条代理请求尝试

说明：稳定路由配置会写回 `config.routing`；运行态统计、路径暂停、探测历史和分析桶保存在应用数据目录的 sidecar 文件中。

## FAQ

### 为什么登录浏览器没有立刻关闭？

- 可能仍在等待你完成登录或通过挑战页
- 当前版本会把登录流程放在独立登录浏览器中，避免打断检测任务
- 若长时间无进展，请检查是否仍停留在验证页或登录页

### 为什么有些站点需要浏览器模式才能检测？

- 某些站点接口会被 Cloudflare、WAF 或登录态限制拦截
- 当前版本会统一识别挑战页并切换到浏览器上下文继续获取数据

### 为什么端点测试不使用路由上游协议？

- 端点测试是独立的 HTTP 生成测试，三个端点各自保存选择
- 它用于确认上游原生支持哪个协议；真实路由才根据接入点设置决定是否转换

### 配置文件损坏了怎么办？

- 应用会先校验配置结构
- 若主配置不可读，会尝试从最近备份恢复
- 同时会保留一份损坏副本，便于后续排查

### 如何迁移到新电脑？

- 通过导出/导入配置迁移
- 或直接恢复本地备份
- 或配置 WebDAV 后从云端恢复

### 支持哪些系统？

- Windows
- macOS
- Linux

其中 Linux 打包已提供，但你的实际兼容性仍取决于本地 Chromium 环境和桌面依赖。
